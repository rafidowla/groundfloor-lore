## Audit findings — the one-line summary

GitNexus is wired into **41 files / 448 references** across source,
docs, configs, hooks, env vars, settings, and skill files. The
deepest hooks live in:

- `packages/lore-plugin-developer/src/{gitnexusProxy.ts, codeIndexer.ts, nativeTools.ts, cli.ts, repoOps.ts}` — Phase 7 deletes/rewrites these.
- `package.json` (`gitnexus 1.4.10` runtime dep) — Phase 7 removes.
- `scripts/hooks/post-commit` — Phase 7 replaces with `lore code analyze --incremental`.
- `AGENTS.md` and project `CLAUDE.md` — auto-regenerated by gitnexus today; Phase 8 ports the generator to the new pipeline.
- `.claude/skills/gitnexus/` — 6 skill files; Phase 8 replaces with `.claude/skills/code-intelligence/`.
- `~/.gitnexus/registry.json` and per-repo `.gitnexus/` directories on user machines — left alone per locked decision; CHANGELOG calls them safe-to-rm post-cutover.

> **Side-effect flag for the new pipeline:** `gitnexus analyze` writes
> `AGENTS.md`, `CLAUDE.md`, and `.claude/skills/gitnexus/` into the
> indexed repo as a side effect of indexing. The new `lore code analyze`
> pipeline must NOT mutate the indexed repo's source tree. Index/cache
> writes belong under the workspace's `.lore/` directory only. Track
> in Phase 3.

## Open Phase 1 carry-ins

Found during Phase 0; resolve in Phase 1 before parser implementation lands:

1. **npm install topology.** `packages/lore-plugin-developer/package.json` declares the new deps (web-tree-sitter, 10 grammars, graphology trio) but `npm install` was deliberately not run in Phase 0. Root `package.json` is still the canonical install target — npm workspaces are not yet wired in. Phase 1 first commit should either:
   - (a) Mirror Atlas deps into the root `package.json` and run install there (simplest; matches the existing `gitnexus 1.4.10` placement), OR
   - (b) Enable npm workspaces by adding `"workspaces": ["packages/*"]` to root `package.json` and running install (cleaner long-term; is its own change).
   Recommended: (a) for Phase 1, schedule (b) as a separate cleanup post-Phase-7.

2. **WASM grammar files.** `packages/lore-plugin-developer/grammars/` is referenced in the plugin `package.json` `atlas.grammars.wasmDir` field but does not exist yet. Create it on first install in Phase 1 — copy `.wasm` files out of each `tree-sitter-*` package's install footprint into `grammars/<lang>.wasm`. Commit the WASM blobs under that path (each is < 1 MB; total < 10 MB).

3. **Performance baseline re-record.** §1.3 numbers used wall-clock `$SECONDS` resolution. Once `parser/index.ts` exposes `parseRepo()`, re-run the baseline at millisecond precision so Phase 1 acceptance has a tight comparison.

4. **Indexed-file gap.** Per audit §1.3, gitnexus skips ~20 % of `git ls-files` output (test fixtures, binary blobs, generated code, .gitignore). The new parser should match this filtering — or document a deliberate divergence — to keep symbol counts comparable.

5. **Post-commit hook noise during Phase 1.** The repo-wide post-commit hook (`scripts/hooks/post-commit`) re-runs `gitnexus analyze` and rewrites `AGENTS.md` / `CLAUDE.md` to reflect the worktree directory name. Throughout Phase 0 we manually `git checkout AGENTS.md CLAUDE.md` after every commit. Phase 1 should plan to either silence this hook for Atlas worktrees or land the new `lore code analyze` replacement early in Phase 3 so the noise stops at source.

5. **Cadence:** ~1 day per walker, ~8 days total. Commit one walker at a time. Each walker commit must pass `tsc --noEmit` + `npm run test:arch` (which now includes the license-check).

6. **License-compliance discipline:** every new `.ts` file inside `src/{parser,resolver,analytics,git,mcp}/` needs the Atlas license header (the `atlas-license-check.mjs` script will fail the commit otherwise). Use the existing stubs as the template.
